In this guide, we will take a look at building forms with [NotForm](https://notform.favorodera.dev/), the headless, schema-driven form library for Vue 3 and Nuxt. We'll cover building forms with the `<Field />` component, adding schema validation using Zod, error handling, accessibility, and more.

NotForm ships as `notform` for Vue and Vite applications, and as `@notform/nuxt` for Nuxt 4. See the [installation guide](https://notform.favorodera.dev/docs/getting-started/installation) for setup.

## Approach

This form leverages NotForm for headless, schema-driven form handling. We'll build our form using the `<Field />` component, which gives you **complete flexibility over the markup and styling**.

- Uses NotForm's `useForm` composable for form state management.
- NotForm's `<Form />` component wraps the native `form` element and handles submit and reset.
- NotForm's `<Field />` component hands a typed field instance to a scoped slot for controlled inputs with validation.
- shadcn-vue `<Field />` components for building accessible forms.
- Client-side validation using Zod, or any other [Standard Schema](https://standardschema.dev) library. No adapter is needed.
- Type-safe field paths and values inferred from the schema.

## Anatomy

Here's a basic example of a form using NotForm's `<Field />` component with a scoped slot and shadcn-vue `<Field />` components.

```vue showLineNumbers {2-4,8-13,18}
<template>
  <NotField v-slot="{ field }" :field="form.field('title')">
    <Field :data-invalid="!field.isValid">
      <FieldLabel :for="field.path">
        Bug Title
      </FieldLabel>
      <Input
        :id="field.path"
        v-model="field.model"
        v-bind="field.events"
        placeholder="Login button not working on mobile"
        autocomplete="off"
        :aria-invalid="!field.isValid"
      />
      <FieldDescription>
        Provide a concise title for your bug report.
      </FieldDescription>
      <FieldError v-if="!field.isValid" :errors="field.errors" />
    </Field>
  </NotField>
</template>
```

`form.field(path)` returns a field instance, and `<NotField />` passes it to its slot. The members used above are:

- `field.model`: a two-way binding to the form value at the field's path. Writing to it does not validate.
- `field.events`: `onBlur`, `onChange`, and `onInput` handlers. They mark the field as touched and trigger validation.
- `field.path`: the dot-notation path of the field, such as `title` or `emails.0.address`. Use it for `id` and `for`.
- `field.isValid` and `field.errors`: the validation state of this field.

::callout
---
icon: true
---
**Note:** NotForm ships its own `Field` and `FieldError` components. To avoid a name clash with the shadcn-vue ones, the examples below import NotForm's `Field` as `NotField` and keep the shadcn-vue `Field` and `FieldError` under their original names. NotForm's own `FieldError` is not needed here, because shadcn-vue's `FieldError` renders the same issue list. In your own code you can alias either side. Just be consistent.
::

In a Nuxt project, `@notform/nuxt` auto-imports the NotForm components. Rename the conflicting ones with the `aliases` option:

```ts showLineNumbers title="nuxt.config.ts"
export default defineNuxtConfig({

  notform: {
    aliases: {
      Field: 'NotField',
      FieldError: 'NotFieldError',
    },
  },
})
```

## Form

### Create a form schema

We'll start by defining the shape of our form using a Zod schema.

::callout
---
icon: true
---
**Note:** This example uses Zod, but you can replace it with any other Standard Schema validation library, such as Valibot or ArkType. The schema must be an **object** schema.
::

```vue showLineNumbers
<script setup lang="ts">
import { z } from 'zod'

const formSchema = z.object({
  title: z
    .string()
    .min(5, 'Bug title must be at least 5 characters.')
    .max(32, 'Bug title must be at most 32 characters.'),
  description: z
    .string()
    .min(20, 'Description must be at least 20 characters.')
    .max(100, 'Description must be at most 100 characters.'),
})
</script>
```

### Setup the form

Next, we'll use the `useForm` composable from NotForm to create our form instance. The schema is passed directly to `useForm`, and the submit handler is part of the same configuration.

```vue showLineNumbers {2-3,5-14,16-26,30-32}
<script setup lang="ts">
import { Form, Field as NotField, useForm } from 'notform'
import { z } from 'zod'

const formSchema = z.object({
  title: z
    .string()
    .min(5, 'Bug title must be at least 5 characters.')
    .max(32, 'Bug title must be at most 32 characters.'),
  description: z
    .string()
    .min(20, 'Description must be at least 20 characters.')
    .max(100, 'Description must be at most 100 characters.'),
})

const form = useForm({
  schema: formSchema,
  initialValues: {
    title: '',
    description: '',
  },
  onSubmit(data) {
    // Do something with the validated form values.
    console.log(data)
  },
})
</script>

<template>
  <Form :form="form">
    <!-- Build the form here -->
  </Form>
</template>
```

The `Form` component renders a native `<form>`. On submit it validates the whole form and calls `onSubmit` only when the data is valid. The `data` you receive is the schema's **output**, fully typed.

::callout
---
icon: true
---
**Note:** Though not mandatory, provide an entry in `initialValues` for every field you bind. A missing value reaches your schema as `undefined`, so validators report their generic type message instead of your custom one.
::

## Validation

### Client-side Validation

NotForm validates your form data using the schema you pass to the `schema` option of the `useForm` composable. There is no resolver. The schema is the single source of truth for both runtime validation and static types.

```vue showLineNumbers {5-8,11}
<script setup lang="ts">
import { useForm } from 'notform'
import * as z from 'zod'

const formSchema = z.object({
  title: z.string(),
  description: z.string().optional(),
})

const form = useForm({
  schema: formSchema,
  initialValues: {
    title: '',
    description: '',
  },
})
</script>
```

### Validation Modes

By default, a field validates on `blur` and `change`. While typing, it only re-validates once it already has an error, so users see a message when they leave a field and watch it clear as they fix it.

To change this, pass a config object as the second argument of `form.field()`.

```vue showLineNumbers {2-6,10}
<script setup lang="ts">
const title = form.field('title', {
  validateOn: { input: true },
  validationMode: 'eager',
  debounce: 300,
})
</script>

<template>
  <NotField v-slot="{ field }" :field="title">
    <!-- field content -->
  </NotField>
</template>
```

| Option | Description |
| --- | --- |
| `validateOn`| The events that trigger validation: `{ blur?, change?, input? }`. Defaults to `blur` and `change` on, `input` off. |
| `validationMode` | `'eager'` (default): once a field has errors, `input` and `change` re-validate it. `'lazy'`: only the events enabled in `validateOn` validate. |
| `debounce` | Delay in milliseconds for `input` and `change` validation. Blur and submit are never delayed. |


::callout
---
icon: true
---
**Note:** Fields are cached by path and the config is read **once**, when the field is first created. Create each configured field in `<script setup>` and reuse that instance, as shown above. Later calls to `form.field()` with the same path ignore any new config.
::

## Displaying Errors

Display errors next to the field using `<FieldError />`. For styling and accessibility:

- Add the `:data-invalid` prop to the shadcn-vue `<Field />` component.
- Add the `:aria-invalid` prop to the form control such as `<Input />`, `<SelectTrigger />`, `<Checkbox />`, etc.

`field.errors` is an array of issues that each have a `message`, which is the shape shadcn-vue's `<FieldError />` expects.

```vue showLineNumbers {3,12,14}
<template>
  <NotField v-slot="{ field }" :field="form.field('email')">
    <Field :data-invalid="!field.isValid">
      <FieldLabel :for="field.path">
        Email
      </FieldLabel>
      <Input
        :id="field.path"
        v-model="field.model"
        v-bind="field.events"
        type="email"
        :aria-invalid="!field.isValid"
      />
      <FieldError v-if="!field.isValid" :errors="field.errors" />
    </Field>
  </NotField>
</template>
```

::callout
---
icon: true
---
**Note:** A field shows only the issues reported at its exact path. Issues without a path, such as a rule that spans the whole form, are form-level and live in `form.errors`.
::

## Working with Different Field Types

NotForm connects a control to a field through two members, `field.model` and `field.events`. How you wire them depends on what the shadcn-vue component emits:

- **Components that render a native element** (like `Input`, `Textarea`, and `InputGroupInput`) forward native attributes and events. Use `v-model="field.model"` and spread `field.events` with `v-bind`.
- **Components that only emit `update:modelValue`** (like `Select`, `Checkbox`, `RadioGroup`, and `Switch`) don't fire native `input` or `change` events, so `v-bind="field.events"` does nothing for them. Use `v-model="field.model"`, then report the change with `@update:model-value="field.events.onChange"` and focus leaving with `@blur="field.events.onBlur"`.

Always put `v-model` before `v-bind="field.events"`. The value has to be written before the validation event takes its snapshot.

### Input

- For input fields, use `v-model="field.model"` and `v-bind="field.events"`.
- To show errors, add the `:aria-invalid` prop to the `<Input />` component and the `:data-invalid` prop to the shadcn-vue `<Field />` component.

- To show errors, also add the `:data-invalid` prop to the shadcn-vue `<Field />` component.

- For a single boolean checkbox, use `v-model="field.model"` on `<Checkbox />` and a boolean schema such as `z.boolean()` or `z.literal(true)`.

For an array field, read the current selection from `field.model`, assign the next array, then call `field.events.onChange()` so validation runs against the new value.

```vue showLineNumbers {16-26}
<template>
  <NotField v-slot="{ field }" :field="form.field('tasks')">
    <FieldSet :data-invalid="!field.isValid">
      <FieldLegend variant="label">
        Tasks
      </FieldLegend>
      <FieldDescription>Get notified when tasks you've created have updates.</FieldDescription>
      <FieldGroup data-slot="checkbox-group">
        <Field
          v-for="task in tasks"
          :key="task.id"
          orientation="horizontal"
          :data-invalid="!field.isValid"
        >
          <Checkbox
            :id="`${field.path}-${task.id}`"
            :model-value="field.model?.includes(task.id)"
            :aria-invalid="!field.isValid"
            @blur="field.events.onBlur"
            @update:model-value="(checked: boolean | 'indeterminate') => {
              field.model = checked === true
                ? [...(field.model ?? []), task.id]
                : (field.model ?? []).filter((id: string) => id !== task.id)

              field.events.onChange()
            }"
          />
          <FieldLabel :for="`${field.path}-${task.id}`" class="font-normal">
            {{ task.label }}
          </FieldLabel>
        </Field>
      </FieldGroup>
      <FieldError v-if="!field.isValid" :errors="field.errors" />
    </FieldSet>
  </NotField>
</template>
```

Give each checkbox a unique `id` by appending the item's id to `field.path`.

## Resetting the Form

A `type="reset"` button inside `<Form />` calls `form.reset()` for you, restoring the initial values and errors and clearing the touched state.

```vue showLineNumbers {10-12}
<script setup lang="ts">
const form = useForm({
  schema: formSchema,
  // ...
})
</script>

<template>
  <Form :form="form">
    <Button type="reset" variant="outline">
      Reset
    </Button>
  </Form>
</template>
```

Outside of `<Form />`, call `form.reset()` yourself.

```vue showLineNumbers
<template>
  <Button type="button" variant="outline" @click="form.reset()">
    Reset
  </Button>
</template>
```

Reset restores the **baseline**, not a blank form. Pass values to start from a new baseline, for example after loading saved data. The values you pass replace the old baseline, they are not merged with it.

```ts showLineNumbers
// Replace the baseline, then reset to it.
form.reset({ title: 'Login button not working', description: '' })
```

## Array Fields

NotForm provides an `ArrayField` component for managing dynamic array fields. Use it whenever you need to add, remove, or reorder items. Each item keeps a stable identity, and errors stay attached to the right item as the list changes.

### Using ArrayField

Create the array field with `form.arrayField(path)` and pass it to the `ArrayField` component. It provides `arrayField` through its slot, with an `items` list and mutation methods such as `append` and `remove`.

```vue showLineNumbers {6-8}
<script setup lang="ts">
import { ArrayField } from 'notform'
</script>

<template>
  <ArrayField v-slot="{ arrayField }" :array-field="form.arrayField('emails')">
    <!-- Array items go here -->
  </ArrayField>
</template>
```

### Array Field Structure

Wrap your array fields in a `<FieldSet />` with a `<FieldLegend />` and `<FieldDescription />`. Errors for the list as a whole, such as a minimum or maximum item count, come from `arrayField.errors`.

```vue showLineNumbers
<template>
  <ArrayField v-slot="{ arrayField }" :array-field="form.arrayField('emails')">
    <FieldSet class="gap-4" :data-invalid="!arrayField.isValid">
      <FieldLegend variant="label">
        Email Addresses
      </FieldLegend>
      <FieldDescription>
        Add up to 5 email addresses where we can contact you.
      </FieldDescription>
      <FieldGroup class="gap-4">
        <!-- Array items go here -->
      </FieldGroup>
      <FieldError v-if="!arrayField.isValid" :errors="arrayField.errors" />
    </FieldSet>
  </ArrayField>
</template>
```

### Field Pattern for Array Items

Map over `arrayField.items` and create a field for each item with `item.field(path)`. Paths are relative to the item and follow it when it moves. **Make sure to use `item.id` as the key**.

```vue showLineNumbers {2,4-7}
<template>
  <ArrayField v-slot="{ arrayField }" :array-field="form.arrayField('emails')">
    <NotField
      v-for="item in arrayField.items"
      :key="item.id"
      v-slot="{ field }"
      :field="item.field('address')"
    >
      <Field orientation="horizontal" :data-invalid="!field.isValid">
        <FieldContent class="flex-1">
          <InputGroup>
            <InputGroupInput
              :id="field.path"
              v-model="field.model"
              v-bind="field.events"
              type="email"
              placeholder="name@example.com"
              autocomplete="email"
              :aria-invalid="!field.isValid"
            />
            <!-- Remove button -->
          </InputGroup>
          <FieldError v-if="!field.isValid" :errors="field.errors" />
        </FieldContent>
      </Field>
    </NotField>
  </ArrayField>
</template>
```

::callout
---
icon: true
---
**Note:** Don't key the list by index. After an insertion or reorder the same item has a different index, and an index key makes Vue reuse the wrong DOM and component state. `item.id` is stable. `item.index` and `item.path` follow the item's position.
::

### Adding Items

Use the `append` method to add new items to the array. Values are deep-cloned, so two items never share an object. `prepend` and `insert` work the same way.

```vue showLineNumbers
<template>
  <Button
    type="button"
    variant="outline"
    size="sm"
    :disabled="arrayField.items.length >= 5"
    @click="arrayField.append({ address: '' })"
  >
    Add Email Address
  </Button>
</template>
```

### Removing Items

Use the `remove` method with the item's `index` to remove items from the array. Add the remove button conditionally.

```vue showLineNumbers
<template>
  <InputGroupAddon v-if="arrayField.items.length > 1" align="inline-end">
    <InputGroupButton
      type="button"
      variant="ghost"
      size="icon-xs"
      :aria-label="`Remove email ${item.index + 1}`"
      @click="arrayField.remove(item.index)"
    >
      <XIcon />
    </InputGroupButton>
  </InputGroupAddon>
</template>
```

NotForm also exposes `move`, `swap`, and `update` for reordering and replacing items. For example, `arrayField.move(item.index, item.index - 1)` moves an item up. Always change the array through these methods. Mutating `form.values.emails` directly with `push`, `splice`, or `sort` bypasses the identity and error tracking.

### Array Validation

Use Zod's `array` method to validate array fields. Every mutation re-validates the array's own path, so a "minimum items" error appears or clears immediately.

```ts showLineNumbers
const formSchema = z.object({
  emails: z
    .array(
      z.object({
        address: z.string().email('Enter a valid email address.'),
      }),
    )
    .min(1, 'Add at least one email address.')
    .max(5, 'You can add up to 5 email addresses.'),
})
```
